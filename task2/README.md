# ПОС — Преподавательская оценка студентов

Это небольшое консольное приложение для учёта оценок студентов. В нём можно завести студентов, составить рубрикатор, выставить или исправить баллы, посмотреть итог и выгрузить его в CSV. Проект написан на Go 1.22. Для ID используется библиотека `github.com/google/uuid`.

## Как запустить

Из корня проекта:

```bash
go run ./cmd/pos
```

Меню подсказывает, какие данные нужно ввести. В нём можно добавлять, просматривать, менять и удалять студентов и критерии. ID при создании вводить не нужно: программа генерирует его сама и показывает на экране. Этот ID понадобится, когда захочется изменить или удалить запись либо выставить оценку. Оценка по одной паре «студент — критерий» хранится одна: если выставить её повторно, прежний балл заменится. Оценку также можно отменить.

Чтобы сразу увидеть, как всё работает, запустите готовый сценарий. Программа создаст двух студентов и три критерия, выставит оценки, попробует поставить 12 из 10 и использовать несуществующий критерий, а затем посчитает итоги и сохранит результат Анны в CSV:

```bash
go run ./cmd/pos -demo -out demo_result.csv
```

В этом сценарии у Анны получается 87%, у Бориса — 35%. Проверить сборку и тесты можно так:

```bash
go build ./...
go test ./...
golangci-lint run ./...
```

Для последней команды нужен [golangci-lint v2](https://golangci-lint.run/docs/welcome/install/local/). Его настройки лежат в `.golangci.yml`.

Данные живут в памяти только до завершения программы. CSV нужен для выгрузки итога одного студента; он не сохраняет весь рубрикатор для следующего запуска.

## Как получается итог

У каждого критерия есть максимальный балл и целый положительный вес. Сначала оценка переводится в долю от максимума, затем умножается на вес. Сумма таких вкладов делится на сумму весов и переводится в проценты. Например, веса 50 и 30 дадут тот же результат, что 5 и 3: важны их пропорции.

Если оценка по критерию ещё не выставлена, её вклад равен нулю. Рядом с итогом программа показывает, сколько критериев уже оценено. По желанию можно запустить `-policy equal`: тогда все критерии влияют на итог одинаково. В демонстрации результат Анны при таком правиле — 90%.

Программа не примет балл меньше нуля или выше максимума и не даст выставить оценку по критерию, которого нет в рубрикаторе. Критерий с выставленными оценками нельзя удалить. Его максимум можно изменить, только если существующие оценки остаются в допустимом диапазоне.

## Как устроен проект

Названия в коде взяты из самой задачи: `Student` — студент, `Criterion` — критерий, `Evaluation` — оценка, `Rubric` — рубрикатор, `Result` — итог. Студент, критерий и оценка — сущности с идентичностью; оценку определяет пара идентификаторов студента и критерия. `Score` и `Result` — объекты-значения. `Rubric` собирает критерии в один агрегат и не допускает повторных идентификаторов.

Итог считает `Calculator` из `internal/calculation`. Это доменный сервис: для расчёта ему нужны весь рубрикатор и оценки конкретного студента. Отдельной сохранённой цифры итога нет, поэтому после исправления оценки результат сразу меняется. Хранение описано портами `StudentRepository`, `RubricRepository` и `EvaluationRepository`, а реализует их `MemoryStore`.

В проекте использована облегчённая архитектура Ports and Adapters. `internal/domain` содержит модели и их проверку, `internal/calculation` — расчёт результата, `internal/app` — сценарии и порты, `internal/console`, `internal/storage` и `internal/export` — ввод, хранение и CSV. В `internal/bootstrap` собираются зависимости и разбираются параметры запуска, а `cmd/pos/main.go` только запускает программу. Модели и расчёт не знают о консоли и файлах.

## Зачем здесь паттерны

**Фабрика** `EvaluationFactory` создаёт оценку только после проверки критерия и диапазона балла. Благодаря этому правило не приходится повторять в разных частях программы.

**Фасад** `app.Service` связывает действия пользователя с моделью и хранилищем. Например, при экспорте он находит студента, рассчитывает актуальный итог и передаёт его CSV-адаптеру. Консоли не приходится управлять этими шагами.

**Стратегия** `calculation.ResultPolicy` позволяет менять правило подсчёта. По умолчанию используется `WeightedPolicy`, а `EqualPolicy` можно выбрать параметром `-policy equal`. Сам `Calculator` при этом менять не нужно.

## Использование ИИ

ИИ помог с теорией по языку go для данного проекта, помог проверить сборку и демонстрационный запуск.
